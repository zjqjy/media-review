# 自媒体复盘系统 · 设计文档

> 需求原文见 [[06_归档/2026-09-16_自媒体复盘系统搭建|自媒体复盘系统搭建]]（已归档）。项目入口 [[CLAUDE.md|项目 CLAUDE]]。

## 一、痛点与目标

当前视频发出去之后靠人工复盘，能力有限、无反馈、不知道优化点在哪。目标：做成 Claude Code skill，发布后自动取数、按本 vault 的自媒体方法论归因、产出可执行的改动清单并回写知识库。

## 二、调研结论（2026-09-16）

### 平台数据获取风险

| 平台 | 方案 | 风险 | 结论 |
|---|---|---|---|
| B站 | 自己账号 Cookie 调创作中心接口（bilibili-API-collect 有"创作中心→统计与数据"文档，配套 Python 库 `bilibili-api`） | 低——取自己的数据，非爬虫 | ✅ 全自动 |
| 抖音 | 官方开放平台：「视频查询」+「视频数据」能力，OAuth 取数 | 无风险但流程繁琐（实名+建应用+申请能力） | ⚠️ M3 备选，MVP 手动 |
| 小红书 | 无官方个人 API；爬虫撞"阿瑞斯"风控（AI 实时预审，轻则限流重则封号） | 高 | ❌ 不爬，永久手动 |

### GitHub 现成轮子

| 项目 | 评估 |
|---|---|
| [Easel](https://github.com/ZJU-REAL/Easel)（浙大） | 最接近（AI 社媒智能体，含内容效果分析），但是独立平台，重、不联动本知识库 → 不采用 |
| [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)（30K★） | 爬别人的公开数据，非复盘自己账号，且有风控风险 → 不采用 |
| xiaobei | 企业向运营套件，有数据复盘工作流，独立平台 → 不采用 |

**结论**：数据获取层站在 bilibili-API-collect 肩上；"联动知识库 + 方法论归因"无人能做，自建 skill。

## 三、已确认决策（2026-09-16，用户逐项拍板）

1. **复盘粒度**：先做单条内容复盘（发布后 D+3/D+7/D+30 三个观察点），数据攒起来后做账号周期复盘
2. **数据输入**：B站全自动 + 抖音/小红书手动粘贴（抖音官方 API 以后有需要再接）
3. **触发方式**：手动喊 `/media-review`，skill 自动清算所有"今天到了观察点"的内容，无状态零维护
4. **写回机制**：报告 + 半自动写回——报告末尾给"建议写回"清单，用户确认后才写入选题池/复用片段/对标。理由：方法论铁律"选题验证不能 AI 替代"，数据好≠选题被验证

## 五、数据输入

- **B站自动轨**：`fetch_bili.py` 用 Cookie 拉创作中心投稿列表（首次全量盘点历史投稿，之后增量）+ 单视频数据；自动按发布日期算 D+3/D+7/D+30 是否到期。Cookie 失效直接报错提示更新，不猜。API 失败重试一次，仍失败降级为手动粘贴模式
- **手动轨（抖音/小红书）——截图收件箱模式**（2026-09-16 定稿，替代"对话贴图"方案）：
  - **收集端**：收集窗口 `scripts/screenshot_tray.py`（tkinter+Pillow，置顶小窗）——**复盘时由 skill 启动，非常驻**（复盘是集中时间做的事，贴完即关，无托盘/无自启/无热键）。截图后点窗 Ctrl+V 连续贴多张，图落 `20_自媒体/复盘/_截图收件/`，文件名 `yyyyMMdd-HHmmss_平台.png`，平台下拉可选（抖音/小红书/自动识别），"完成"按钮关闭并结束收集
  - **消费端**：复盘时 skill 批量读收件目录，逐张多模态识别平台/标题/数据指标，对号入座写进报告；识别不了的图留下等用户备注；处理完的图移 `06_归档/截图收件备份/` 留痕
  - **抖音 Excel 导出**：复盘时给文件路径，直接读
  - `_发布登记.md` 只填元数据四项（平台/标题/发布日期/链接），数据本体靠截图，不手打数字
- 发布 <3 天的内容只登记不复盘

## 六、诊断框架（方法论映射）

爆款公式：**爆款 = 选题 × 素材 × 内容**（[[30_方法论/自媒体方法论体系|方法论总纲]] §2），复盘 = 对已发布内容做三要素归因：

| 要素 | 数据信号（B站创作中心） | 归因 |
|---|---|---|
| 选题 | 播放量 vs 粉丝基线、CTR、播放来源分布 | 播放低 = 选题没踩中 or 封面标题不行 |
| 素材 | 赞/播比、评论区"我也遇到过"类共鸣占比 | "自己的东西"够不够独特 |
| 内容 | 完播率、评论流失点 | "爱听的方式"行不行 |
| 对标 | 同选题 vs [[20_自媒体/对标]] 笔记里的数据 | 差距在哪、抄什么操作 |

输出：三要素各一句话结论 + **下条改动最多 3 条**（可执行，不写空话）+ 建议写回清单。

## 七、报告与写回

- 报告：`20_自媒体/复盘/YYYY-MM-DD_平台_标题.md`，一条内容**一份文件**，D+3/D+7/D+30 追加数据快照段落，不新建。frontmatter 按 vault 规范（`type: 复盘`…`## 相关` 双链方法论/对标/同选题历史复盘）
- 写回：报告末尾"建议写回"清单（checkbox），用户确认后 skill 写入选题池/复用片段/对标笔记，写完勾掉留痕

## 八、错误处理与测试

- Cookie 失效 → 明确报错；<3 天 → 只登记；API 挂 → 重试一次→降级手动
- `fetch_bili.py --dry-run` 不写盘；诊断逻辑用 fixtures 测，不真连 B站

## 九、里程碑

- **M1（MVP）**：B站单条复盘全自动 + 手动平台登记/粘贴 + 报告 + 半自动写回
- **M2**：账号周期复盘（月度报告），吃 M1 攒的报告
- **M3（可选）**：Codex automation 定时套壳；抖音官方 API

## 十、开放问题

1. B站创作中心接口的具体字段与 wbi 签名——实现阶段对着 bilibili-API-collect 文档确认
2. 完播率等数据在创作中心接口里的可得性——同上，拿不到就在报告里标注"数据不可得"
