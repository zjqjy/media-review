# media-review · 自媒体复盘

按爆款公式 **爆款 = 选题 × 素材 × 内容**（三缺一）对已发布内容做归因复盘。方法论依据：vault `30_方法论/自媒体方法论体系.md`。

## 前置

- 配置：`<vault>/20_自媒体/复盘/_config_local.json`（含 B站 SESSDATA；vault 路径未知时先问用户）
- Cookie 未配置/失效时，让用户自己跑：`python scripts/fetch_bili.py login --config "<vault>/20_自媒体/复盘/_config_local.json"` → 二维码图片自动弹出 → B站 App 扫码 → SESSDATA 自动写入配置（需 `pip install qrcode`）。用户也可 F12 手动复制
- 脚本：本 skill 目录下 `scripts/fetch_bili.py`（取数零依赖；login 另需 qrcode）；收集窗 `scripts/screenshot_tray.py`（需 Pillow）
- 若当前工作目录就是 vault（能找到 `20_自媒体/复盘/`），所有路径相对 cwd

## 流程

### 1. 清算到期观察点

```bash
python scripts/fetch_bili.py list --config "<vault>/20_自媒体/复盘/_config_local.json"
```

得到 `due_watchpoints`（今天到期的 D+3/D+7/D+30 列表）。同时扫两处手动来源：

- `20_自媒体/复盘/_发布登记.md`：手动平台（抖音/小红书）条目，按发布日期算到期
- `20_自媒体/复盘/_截图收件/`：已有截图（上次收的）

汇总成"待复盘清单"。**空则结束**：告知最近一个到期日，不硬凑。

### 2. 取数

- **B站**：`fetch_bili.py diagnose --config ...`（完播率/3秒退出率/CTR/涨粉，按 bvid 与 list 的 stat 合并）；首跑或用户问基线时再跑 `overview`（总粉丝数，算播放基线：粉丝基数小的号播放浮动大，别用绝对值吓人）；判断选题/分发问题时可跑 `playsource`（播放来源占比，**账号级**数据，只作参考不作单视频归因依据）
- **抖音/小红书**：启动收集窗（后台、不阻塞）：

```bash
python scripts/screenshot_tray.py --dir "<vault>/20_自媒体/复盘/_截图收件"
```

告诉用户："把创作中心截图 Ctrl+V 贴进弹出的窗口，贴完点完成收集/直接跟我说完事"。用户说完成或窗口关闭后，读 `_截图收件/` 里的图，逐张识别：平台、标题、发布时间、播放/完播/点赞/收藏/涨粉等数字。

### 3. 逐条诊断（三要素归因）

对每条待复盘内容，读上面数据 + 该内容对应的分镜草稿/口播稿（若有），按下表归因。**信号先行，结论后置**——先摆数据，再下判断，禁止无数据空谈：

| 要素 | 看什么 | 解读 |
|---|---|---|
| 选题 | 播放量 vs 自己近期基线；CTR（tm_rate）；播放来源 | 播放低+CTR低 → 选题/封面标题没踩中；CTR 正常播放低 → 分发问题 |
| 素材 | 赞/播比；评论区"我也遇到过/这就是我"类共鸣占比 | "自己的东西"不独特 → 数据平但无人共鸣 |
| 内容 | 完播率（full_play_ratio）；3秒退出率（crash_rate）；评论流失点 | 开头流失 → 前3秒钩子；中后段流失 → 节奏/信息密度 |
| 对标 | 同选题 vs `20_自媒体/对标/` 笔记里同体量账号的数据 | 差距可解释 → 抄操作；不可解释 → 对错对标 |

输出每条：三要素各一句话结论 + **下条改动最多 3 条**（可执行、可验证，如"下条把结果放开头 3 秒"，不写"要提升内容质量"这类空话）。

### 4. 写报告

路径：`20_自媒体/复盘/YYYY-MM-DD_平台_标题.md`（发布日期）。**一条内容一份文件**，D+3/D+7/D+30 观察点追加更新同一文件：

- 首次：按模板建文件（frontmatter `type: 复盘`，tags 含平台和选题词，status: 沉淀，sources 放内容链接）
- 再次：在最新"数据快照"段后面追加 `## 数据快照（D+N，日期）`；只有出现显著变化（如完播率跳变）才补 `## D+N 修正` 小节，修正归因

```markdown
---
type: 复盘
tags: [复盘, B站, <选题tag>]
status: 沉淀
created: <发布日期>
sources:
  - <内容链接>
---
```

### 5. 写回（确认制，铁律）

报告末尾"建议写回"清单逐条向用户确认，**用户点头才动笔**；写完把对应 checkbox 勾掉。写入目标：

- 选题池 `20_自媒体/选题池/`：只写"数据验证过的选题信号"，注明是哪个视频验证的（数据好≠选题被验证，最终判断留给用户）
- 复用片段 `20_自媒体/复用片段/`：这次好用过的钩子/结构/表达
- 对标 `20_自媒体/对标/<名字>.md`：补数据快照或新操作发现

### 6. 收尾

- 处理完的截图移 `06_归档/截图收件备份/`（文件名前缀复盘日期）
- vault 改动 `git add . && git commit -m "AI: 复盘 <标题> D+N"`
- 汇报：本次复盘几条、最关键的一个发现、下次观察点日期

## 错误处理

| 情况 | 动作 |
|---|---|
| Cookie 失效（脚本 code -101） | 让用户去 B站网页 F12 复制新 SESSDATA 进 `_config_local.json`，重跑 |
| 接口挂 | 重试一次；仍失败 → 让用户直接截图创作中心，走收集窗人工轨 |
| 截图识别不出 | 图片留在收件目录，请用户备注（哪条视频/哪个数字），不猜 |
| 发布 <3 天 | 只在登记文件标记，不复盘 |

## 红线

- 只取**自己账号**数据；不给脚本加任何爬取他人内容的能力
- 选题/素材系统的方法论铁律：验证机制是人的品味，AI 只出信号不替用户拍板
- Cookie 不写入任何 git 跟踪的文件
