# media-review · 自媒体复盘（按期）

**核心概念：期 = 同一主题内容的一次多平台发布组合**（B站视频 + 抖音 + 小红书）。用户三平台统一发布，B站数据自动拉，抖音/小红书复盘时主动向用户要截图。复盘单位是"期"，不是单平台单条。

按爆款公式 **爆款 = 选题 × 素材 × 内容**（三缺一）归因。方法论依据：vault `30_方法论/自媒体方法论体系.md`。

## 前置

- 配置：`<vault>/20_自媒体/复盘/_config_local.json`（含 B站 SESSDATA；vault 路径未知时先问用户）
- Cookie 未配置/失效时，让用户自己跑：`python scripts/fetch_bili.py login --config "<vault>/20_自媒体/复盘/_config_local.json"` → 二维码图片自动弹出 → B站 App 扫码 → SESSDATA 自动写入配置（需 `pip install qrcode`）。用户也可 F12 手动复制
- 脚本：本 skill 目录下 `scripts/fetch_bili.py`（取数零依赖；login 另需 qrcode）；收集窗 `scripts/screenshot_tray.py`（需 Pillow）
- **逐字稿**：数据之外必须结合内容本身。取数阶段主动向用户要**本期剪辑后的逐字稿**（粘贴文本即可；还没剪完就用大纲顶，标注"大纲版"；`复盘/逐字稿/` 下已有本期文件——/media-cut 粗剪归档的副产物——则直接读，不再要）。逐字稿用于：开头钩子分析（对照留存曲线的流失时间点）、结构 vs 数据对照（哪段内容对应 retention 凸起/崩塌）、口播质量。只看数据不看内容 = 只能说"开头差"，说不了"为什么差、怎么改"。**收到后落盘存档**：`20_自媒体/复盘/逐字稿/第N期_标题_逐字稿.md`（保留原文含口误，frontmatter 标期数，双链复盘报告），报告"相关"节回链
- 若当前工作目录就是 vault（能找到 `20_自媒体/复盘/`），所有路径相对 cwd

## 流程

### 1. 核对改进实验（反馈闭环，先于一切）

读 `20_自媒体/复盘/_改进实验.md`，列出所有 `状态: 待验证` 的实验。对每条，找本期到期内容里对应的验证数据：

- **数据变好（达到验证标准）** → 判定"有效"，向用户确认后：状态改`已验证有效`+填结论，并建议把该方法写入 `20_自媒体/复用片段/`（确认制）
- **数据没变好/变差** → 状态改`已验证无效`+一句分析（假设错在哪），不沉淀
- 跟本期无关的实验保持待验证，不动

这一步的产出（"上期改的 X 这期验证有效/无效"）要写进最终汇总报告的开头。

### 2. 清算到期观察点

```bash
python scripts/fetch_bili.py list --config "<vault>/20_自媒体/复盘/_config_local.json"
```

得到 `due_watchpoints`（今天到期的 D+3/D+7/D+30 列表）——**这是本期复盘的主轴**，每条 B站视频代表一期。过滤掉报告里已有该观察点段落的（报告即状态）。空则告知最近到期日，结束，不硬凑。

随即取数（每条到期视频）：

- `fetch_bili.py diagnose --config ...`——完播率/3秒退出率/CTR/涨粉，按 bvid 与 list 的 stat 合并
- `fetch_bili.py overview --config ...`——粉丝基线（首跑或用户问基线时；粉丝基数小的号播放浮动大，别用绝对值吓人）

深度诊断（逐条归因"内容"要素时用）：

```bash
python scripts/fetch_bili.py retention --bvid BVxx --config "..."
```

返回单稿件三件套：**逐5秒流失曲线**（`viewer_quit` 我方 vs `peer_viewer_quit` 同类对照，精确定位中后段流失时间点）+ **B站 AI 解读**（星级评分/tip 文案）+ 稿件详情（pubtime/cid）。注意：`playsource`（页面来源占比）2026-09 已随 v3 数据中心改版下线，无法恢复；来源分析改用 retention 曲线，必要时人工瞟创作中心网页。

### 3. 主动关联同期抖音/小红书（不依赖登记表）

**对每条到期的 B站视频，主动问用户**："《标题》这期同期发抖音/小红书了吗？"——用户三平台统一发布，大概率发了，且复盘时用户会主动去找截图。不要因为登记表是空的就跳过（`_发布登记.md` 只是可选线索）。

用户说发了 → 启动收集窗。**必须以后台任务方式启动**（不阻塞对话），窗口关闭 = 进程退出 = 自动收到完成通知，无需用户回话确认：

```bash
python scripts/screenshot_tray.py --dir "<vault>/20_自媒体/复盘/_截图收件"
```

提示用户："收集窗里**期数填这期的期数**（如 第3期），**平台切到抖音/小红书**（分目录不混），把创作中心数据页截图 Ctrl+V 贴进去，贴完点完成收集（窗口关了我就知道）"。收到进程退出通知后进入收图。用户中途说"贴完了"也同样处理（以磁盘为准，不纠结窗口状态）。

同时扫 `_截图收件/` 下已有子目录——历史期数的图如果还没处理，一并处理。目录结构：`_截图收件/<期数>/<平台>/<时间戳>.png`。

### 4. 收图与配期

- 图按 `<期数>/<平台>/<时间戳>.png` 双级目录组织（收集窗落的，平台不混）；期数是用户在收集窗填的
- **AI 配期**：读图识别标题/内容 → 与 B站视频标题模糊匹配验证期数对不对；用户没填期数（`未分期/`）的图，按截图里的标题自动归期，归不了的原地留着问用户
- 从图里提取：平台、标题、发布时间、播放/点赞/收藏/评论/涨粉/完播（平台有什么提什么）。识别置信度低的数字标 `?`

### 5. 三平台合参诊断

**先单平台信号，再跨平台对比**：

| 维度 | 看什么 | 解读 |
|---|---|---|
| B站选题 | 播放 vs 粉丝基线；CTR（tm_rate）；完播（full_play_ratio） | CTR 低 = 封面标题问题；完播低 = 前3秒钩子/节奏 |
| 内容留存 | retention 逐5秒流失曲线 vs 同类对照（peer_viewer_quit） | 流失尖峰位置 = 该时间点内容问题；对照高 = 全局节奏差，对照低 = 局部坑 |
| 逐字稿 | 开头 15 秒文本（钩子类型：成果前置/自我介绍/任务清单）；结构段落 vs retention 曲线凸起/崩塌的时间对位；口播流畅度 | 开头文本无钩子 = 流失必然；曲线峰值段 = 观众要的内容，检查是否被埋没/该提到开头；语序混乱/口误密集 = 剪辑密度问题 |
| 跨平台对比 | 同一期三平台的播放/互动率/涨粉相对表现 | B站跑赢抖音 → 内容偏深度，反之偏情绪钩子；某平台独好 → 下期该平台改标题封面适配 |
| 素材 | 赞/播比；评论区"我也遇到过"类共鸣占比 | "自己的东西"够不够独特 |
| 对标 | 同选题 vs `20_自媒体/对标/` 笔记里同体量账号 | 差距可解释 → 抄操作；不可解释 → 对错对标 |

每期输出：三要素各一句话结论 + 跨平台一句话结论 + **下条改动最多 3 条**（可执行可验证，如"下条把结果放开头3秒"，不写"提升内容质量"这种空话）。单平台数据缺失就只盘有数据的平台，注明缺谁。

- frontmatter 按 vault 规范（`type: 复盘`，tags 含各平台与选题词，status: 沉淀，sources 放各平台链接）

### 7. 改进实验登记（闭环的"实验"端）

本期报告"下条改动"的每一条，追加登记进 `20_自媒体/复盘/_改进实验.md`：

```
| 登记日期 | 来源期 | 改动 | 假设 | 验证标准 | 状态 | 验证期 | 结论 |
| 2026-09-20 | 第3期 | 前3秒放成品展示 | 成品钩子提完播 | 第4期B站完播率 > 本期 | 待验证 | | |
```

验证标准要可判定（具体指标+方向），写不出标准的改动不登记（那是空话，别进闭环）。

### 8. 写回与收尾（确认制，铁律）

- 报告末尾"建议写回"逐条向用户确认，**点头才动笔**，写完勾 checkbox：
  - 选题池 `20_自媒体/选题池/`：只写数据验证过的选题信号，注明验证来源（数据好≠选题被验证，最终判断留给用户）
  - 复用片段 `20_自媒体/复用片段/`：**含改进实验验证有效的方法**（闭环的沉淀端）
  - 对标 `20_自媒体/对标/<名字>.md`：补数据或新操作发现
- **更新 `20_自媒体/复盘/_下期规划参考.md`**：把本期"下条改动"的新结论合并进去（替换已过时条目），这份文件是下期内容规划的直接输入——闭环的"复盘→规划"接口
- 处理完的截图整期移 `06_归档/截图收件备份/<期数>/`
- vault 改动 `git add . && git commit -m "AI: 复盘 第N期 <标题> D+N"`
- 汇报：本期三平台概况、改进实验验证结果、最关键的一个发现、下次观察点日期

## 错误处理

| 情况 | 动作 |
|---|---|
| Cookie 失效（脚本 code -101） | 让用户重跑 login 扫码，或 F12 手动更新 |
| 接口挂 | 重试一次；仍失败 → 让用户截图创作中心，走收集窗人工轨 |
| 截图配不上期/识别不出 | 图留在原地，问用户（哪期/哪个数字），不猜 |
| 用户说某期没发抖音/小红书 | 该期按 B站单平台盘，报告数据表空列划掉 |
| 发布 <3 天 | 只登记，不复盘 |

## 红线

- 只取**自己账号**数据；不给脚本加任何爬取他人内容的能力
- 选题/素材系统的方法论铁律：验证机制是人的品味，AI 只出信号不替用户拍板；改进实验"有效"的判定标准在复盘时由用户确认
- Cookie 不写入任何 git 跟踪的文件
