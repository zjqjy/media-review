# benchmark · 找对标与拆解模仿（B站）

对标 = 抄作业的对象。本技能做四件事：**找**（搜索/翻对标UP的爆款）→ **拉**（视频+逐字稿+评论落盘）→ **拆**（按爆款 = 选题×素材×内容拆解成对标笔记）→ **用**（可模仿要素进选题池/下期规划，复盘时"对标校准"直接引用）。多平台博主 B站基本都同步发，且 B站可下载、有 AI 字幕、评论区公开——**对标统一在 B站做**，抖音/小红书只在拆完做平台适配。

## 配置与凭据（与大号隔离）

- 配置文件同 review（`_config_local.json`，`--config` 或脚本向上找；没有也能跑公开命令）。
- **小号专用字段 `bench_sessdata`**：下载他人视频比看自己后台风险略高，**绝不复用大号 `sessdata`**——大号是创作中心取数的命根子。没有就跑 `python scripts/bili_bench.py login --config <配置路径>` 扫码（弹窗 → 小号 App 扫 → 自动写 bench_sessdata）。
- 小号 Cookie 影响：space 投稿列表、AI 字幕、1080p 下载；搜索/详情/评论区匿名可用（主站预热+buvid+wbi 签名脚本内建）。
- 下载素材默认落 `<benchmarks>/_下载/<BV号>/`（脚本自动写 .gitignore 防视频进 vault git）；**对标笔记**（文本）落 `<benchmarks>/<UP主名>/`，随 vault git 提交。

## 流程（照表执行，别临场发挥）

| 步 | 动作 | 要点 |
|---|---|---|
| 0 输入 | 问清三件事：赛道关键词？已有对标 UP？还是单条视频链接？ | 三种入口对应不同起步命令 |
| 1 找 | `python scripts/bili_bench.py search "关键词" --limit 20`；有 UP 就列其投稿（见下"space 列表三条路"） | 挑选标准见下节；候选给用户拍板 |
| 2 拉 | `python scripts/bili_bench.py fetch BVxx` | 详情+封面+视频+AI字幕逐字稿一条龙；`--no-video` 只要文字材料 |
| 3 补 | `python scripts/bili_bench.py comments BVxx --n 30` | 高赞评论 = 观众在要什么，拆解必看 |
| 4 拆 | 读逐字稿+看视频，照 `templates/对标拆解模板.md` 写笔记 | 落 `<benchmarks>/<UP主名>/BVxx_标题.md` |
| 5 用 | 可模仿要素确认后写回 | 选题池/`planning_ref`/复盘"对标校准"，全走确认制 |

无 AI 字幕的稿子（脚本会提示）：下载的视频直接进 cut 的转录——`python <media>/cut/scripts/asr_funasr.py <视频路径>`，SRT 落同目录改名 `逐字稿.srt` 再拆。

## space 列表三条路（按顺序试）

1. **脚本** `bili_bench.py space <mid|主页URL>`：space API 2026-10 起被服务端风控（-403，要页面 JS 下发的风控令牌），脚本会自动降级为 card 换 UP 名 → 搜索召回热门稿（近似列表，不全）
2. **浏览器读全量列表（实测最优）**：用 control-browser 技能开 `https://space.bilibili.com/<mid>/video`，点「最多播放」标签后 `domSnapshot()` 直接读全部投稿——标题/播放/时长/发布日期/BV 号全在快照里。**匿名可用**（登录弹窗关掉即可，不耗小号登录态），2026-10 实测 29 条投稿一条不落
3. 都不行 → 让用户从 UP 主页贴 2-3 条爆款视频链接

## 挑对标的判断标准（步骤 1 的筛选依据）

1. **同赛道同体量**：粉丝量级相近或高一档（高一档是"跳一跳够得着"，差两个量级是仰望，学不了执行力）
2. **近 90 天有爆款**：`space --order click` 里播放显著高于该 UP 均值的近作——爆款才有可拆的增量，老爆款可能是时代红利
3. **多条验证**：单条爆款可能是运气，连出 2-3 条同结构的才是方法。步骤 1 找到候选后先看它的爆款是不是结构化复现
4. 给用户的候选单要带**你的判断**：为什么这条值得拆、预期可抄什么（钩子/结构/选题），不只甩链接

## 拆解判断规则（步骤 4，AI 的核心活）

- **逐字稿是主材料，视频是校验**：先读逐字稿划结构段（开头钩子/正文块/转场句/结尾 CTA），再看视频确认画面手法（花字/录屏/素材比例）。只看视频不读稿 = 拆不出节奏
- 开头 15 秒逐字引用并归类钩子类型（成果前置/悬念/痛点场景/身份认同/反常识）；对照它的完播表现判断钩子强度
- 结构段标时间轴：每段讲什么、占多少秒、信息密度（条/分钟）。工具类内容重点看**清单感**怎么维持的（同 cut 认知②）
- 评论区高赞 = 观众实际要什么：高频疑问是下期选题机会，"我也遇到过"类共鸣是素材独特性信号，直接写进笔记"评论区信号"节
- 模仿红线：**抄结构和方法，不抄内容和表达**。可模仿清单只写可执行动作（"开头 3 秒放成品效果"），不写"学他接地气"这种空话

## 写回（确认制，铁律）

- 对标笔记写完先给用户看，点头才落 `<benchmarks>/`；可模仿要素要进选题池/`planning_ref` 单独确认（同 review 写回规矩）
- 复盘时 review 的"对标校准"直接读这些笔记——笔记里"与我的差距"节要写清**用我哪一期的数据对齐**（如"我第 3 期完播 12% vs 它同类视频约 25%"）
- 同一 UP 拆第二条时笔记放同一目录，新增"复看笔记"节对照上次拆解是否应验

## 错误处理

| 情况 | 动作 |
|---|---|
| HTTP 412 / code -352 | 风控。等几分钟再试；反复出现跑 login 上小号态、或换网络；**别缩短 RATE 限速硬刚** |
| space 报 -403 | space 投稿接口被 B站风控（2026-10 实测连 yt-dlp 都 412）：脚本已自动降级为搜索召回；要全量列表走上面的浏览器路线（实测最优） |
| `space`/`subs` 报缺 bench_sessdata | 跑 `login` 扫码（小号） |
| 无 AI 字幕 | 视频走 cut 转录（asr_funasr.py）；纯画面无口述的对标没有逐字稿，拆结构靠看片标注时间轴 |
| yt-dlp 下载失败 | 看脚本尾部 stderr（尾部 800 字符）；412 类换时段，版权/地区类放弃换对标 |
| 20P 合集类稿子 | cid 默认第一 P；拆哪 P 用 `信息.json` 里 pages 列表 + `subs` 手动流程 |
| 搜出来的都是 0 播放新视频 | search 默认综合排序，加 `--order click` 按播放排 |

## 红线

1. **只用于个人学习拆解**：限速单线程（脚本内建 RATE），单次批量 ≤5 条；禁止批量爬取、禁止做数据服务、禁止二传发布他人视频
2. **只登录小号**：`bench_sessdata` 专属本技能，大号 `sessdata` 绝不进本技能任何命令
3. **模仿结构方法，不搬运内容**：对标笔记是拆解产物不是转载库；下载的视频不进 vault git（脚本已挡），拆完的素材用户自行处置
4. Cookie/敏感信息不进任何 git 跟踪文件
