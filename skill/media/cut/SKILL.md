# cut · 剪辑提效（发前粗剪）

**核心概念：三层漏斗，每层只干一件事。** 痛点是教程类视频 60:1 的素材压缩率（成片 5 分钟，素材 3 小时），最费时的不是精剪，是**看素材选段**。慢的根源是无声素材没有时间索引，只能人眼过——解法不是手快，是让机器先吃掉"确定没用的大段"，人只处理剩下的。

## 两个关键认知（所有决策的依据）

1. **改造录制习惯比换工具更值**：录屏时同步口述（说得烂没关系，反正要剪）——口述就是时间标记 + 内容索引，转录后剪辑从"看片"变"改稿"，且转录产物就是逐字稿（review 的输入自动就有了）。素材全程无口述（纯操作无声）→ 第①层只能砍冷场，第②层无从下手，提醒用户**下期**录制时加口述
2. **工具类内容在抖音，收藏率比完播率重要**（8.94 万那条完播才 0.99%）——粗剪别死磕完播，把"可以存着照做"的清单感做出来

## 前置

- **依赖核验一律走 `python scripts/env_check.py`，不要手工逐个试**（2026-09-20：手工验依赖实测烧 ~6 min/期）。首跑全查几秒（用 importlib.metadata 查版本，**不 import torch/funasr**），结果缓存到技能安装目录 `_env_verified.json`；之后每期秒读缓存跳过。装了新包/换环境后 `--force` 刷新；缓存 30 天自动过期重查
- **转录**：自研 `scripts/asr_funasr.py`（FunASR Paraformer + VAD + 标点，中文 CER ~10%，Whisper 的一半）。依赖 funasr（torch 级，安装需用户点头）；模型走 ModelScope 国内 CDN——**下载模型关 VPN 直连，pip 装包才开 VPN**，首跑 ~1.2G。备选：AutoCut（Whisper，英文素材或要验证它的工作流再装）
- **初选执行器**：`scripts/select.py`（决定.json 进 → 剪切稿+日志出，锚字核验内建）+ `scripts/asr_fixes.json`（跨期沉淀的 ASR 错拼修错表，自动套用）
- **一键编排**：`scripts/run_cut.py`（--init 机器段一条命令 / --finish 收尾一条命令）
- **并行初选**：`scripts/初选代理模板.md`（发子代理时复制替换占位符，见流程第②层 b）
- **ffmpeg** 自动发现：PATH → `imageio_ffmpeg` 自带二进制。都没有 → `winget install ffmpeg` 或 `pip install imageio-ffmpeg`
- **交接脚本**：`scripts/jy_draft.py`（剪映草稿直出）+ `scripts/srt_cut.py`（重编码出粗片，fallback）；均零 ffmpeg 外依赖，复用同一套区间数学
- 逐字稿归档与规划参考的路径走 review 的同一份 `_config_local.json` 配置（`transcripts`/`planning_ref` 键，见仓根 `config.example.json`；不存在的目录首次使用时问用户）；若 cwd 就是知识库根，相对路径直接用

## 流程

### 0. 判断入口（不必每期都从头）

| 用户现状 | 入口 |
|---|---|
| 还没录 / 在规划 | 先讲认知①（口述录制），这是最大的效率杠杆 |
| 只有原始素材 | 从第②层转录开始（原素材直转，见下） |
| 已有带时间戳的转录稿（md/srt） | 跳过转录，直接做 AI 初选 |

### 1. 第①层：静音压缩——已退役为可选预览（2026-09-19 零重编码改造落地）

物理重编码 trimmed.mp4 对③层冗余（jy_draft 引用原素材且自带区间内静音细剪），且实测是管线最大耗时（~13.5 min）。**默认整层跳过**，`silence_trim.py` 保留两个用途：用户要先看压缩版预览；或最终交付要独立粗片文件时手动跑。全流程时间轴一律用**原始素材时间轴**，不再有 trimmed 重映射。

### 2. 第②层 a：转录（FunASR，原素材直转，单批全量）

```bash
python scripts/asr_funasr.py 原素材1.mp4 原素材2.mp4 ... --hotword "ESP32 乐鑫 IDF Claude Code"
# 输出 <stem>.srt（每分句带时间戳，原始素材时间轴）+ <stem>.cuts.json（词级时间洞）
# 技术词塞 --hotword；口头禅默认剥"然后"（--strip-filler 可改/关）
```

- **一次进程吃完全部素材**（多文件参数已支持，模型只加载一次省 2-4 min）——不要按"编码完成的先后"分批转录
- **直接吃原素材**，不预压缩：VAD 天然跳过静音，30 min 素材（9 min 有效语音）CPU 实测 ~1.5 min 出稿，转录不再是瓶颈
- 产出全是**原始素材时间轴**，③层 jy_draft 直接引用原素材，时间戳零换算
- 词级洞三类：分句首口头禅（半角逗号分句后"按…，然后…"也能剥）、句内叠词（含英文 "Claude Code Claude Code"）、重录对前遍。字幕文本同步剥字，音画一致
- **超长条兜底（2026-09-20）**：分句后仍 >25 显示宽度的条目，转录端在词级停顿（≥0.2s）处二次切分；连读无停顿的不硬拆，显示层断行 + 标注轨 [拆条] 兜住
- CPU 几分钟出稿（Paraformer 非自回归架构，CPU 亲和，无需 GPU），**后台任务跑**。首跑下载 ~1.2G 模型（ModelScope 国内 CDN，**关 VPN 直连**）
- 识别仍有错 → 常见错拼直接加进 `scripts/asr_fixes.json`（跨期复用），条目特有的进初选决定.json 的 fixes。用户已有其他渠道转录稿（srt/md 均可）→ 直接用，不重转
- 出现"token ≠ 时间戳，按比例兜底"警告 → 词级洞全丢（时间戳失真），必须先修（脚本会自动试撇号/连字符合并，仍失败查怪字符）再重跑

### 3. 第②层 b：AI 初选（select.py 标准执行器 + AI 判断）

> **多代理初选（2026-09-20 定，短视频场景的命门）**：素材就位后管线计算只要 ~2 min，
> 40+ min 大头是 AI 会话轮次和逐段串行读稿。标准流程三步（实测两期 87min→29:33，见下）：
> 1. **机器段一条命令**：`python scripts/run_cut.py --init 素材目录...`——建工作区+单批转录
>    （一次模型加载，9 段实测 2:11）+逐段 scan 落 `<段>.scan.txt`，打印初选交接单
> 2. **并行子代理初选**：打开 `scripts/初选代理模板.md`，复制替换 {占位符} 后每大段
>    （>15min 素材）发一个子代理、小段合并一组，全部**同时**发出；代理自验锚字后落
>    `_工具/初选决定_<段名>.json` 碎片。实测墙钟=最大段（186 条 18.5min，是全流程关键路径）
> 3. **一条命令收尾**：碎片齐一个跑一个也可——`python scripts/run_cut.py --finish 待粗剪目录...`
>    合并碎片→dry→apply→草稿→organize（短素材 6s，长素材 4:23）
> 时间预算：机器段 ≤3min、并行初选 =最大段 15-20min、收尾 ≤5min。短素材（<5min）
> 整期目标线 **10 分钟内**。全程漏斗数据带时间戳记录

1. 要**内容大纲**：读 `planning_ref` 配置文件（下期规划参考）；没有就用户口述三句——给谁看 / 解决什么问题 / 关键步骤
2. **先跑 `python scripts/select.py --scan <各段>.srt`**：机器预列纯语气词候选、疑似重复组（比转录端重录检测宽：窗口±8条/间隔≤120s）、口头禅统计。AI 只精读扫描出来的候选区+快扫全文，不再逐句硬读大稿
3. AI 拍板写 `初选决定.json`（放转录稿同目录），只写判断不写代码：
   - `iron`：铁废料删条目（纯语气词/乱码无信息）→ 锚字核验
   - `repeat`：语义重复组（用户拍板 2026-09-19：**意思重复=默认重录，删前留后**；组内夹独有内容的先剔除再删，keep_anchors 防删穿）
   - `fixes`：条内修 ASR 错拼（**只修错不改写**口播）
4. **删条目随意、条目内只修错不改写**（剪切只看时间戳：删条目 = 删该段；条目里修错别字/专有名词也安全，SRT 字幕反而更准；但**别合并/拆分条目**——一条对应一段。"收紧"不改正文——改了字，音频还是原话，字幕会和口播对不上，只做标记留给第③层加速或补录）
5. `--dry` 核验（锚字不匹配/保留锚在删除表里会整批拒绝并逐条列出）→ `--apply` 落盘 `<stem>_剪切稿.srt` + `初选日志.json`。**复核单由日志生成附录，不是门禁**（2026-09-19 用户拍板：一步到位，删错的句子用户在剪映里拖回来）
6. 初选时用认知②打分：优先保住"清单感"（步骤完整、结论前置、每步可跳读），别为完播砍步骤

### 4. 第③层：剪映草稿直出（交接形态）

精剪交接的不是粗片文件，是一个**拼好的剪映草稿**（`jy_draft.py`）：

```bash
python scripts/jy_draft.py 原素材.mp4 剪切稿.srt --name "第N期_标题_粗剪"
```

- 主视频轨 = 全部保留区间，**直接引用原素材**（不重编码零损失），剪切点在剪映里仍是可拖动的分割线；区间内静音细剪（`--min-inner 0.8`）由草稿生成时自动做，接替退役的第①层
- 字幕轨 = 剪切稿（已 rebase 到成片时间轴；**显示层断行 ≤16 显示宽/行，ASCII 词不拆散**，条目不拆、时间戳不动；**>25 宽的超长条自动进标注轨 [拆条]** 提醒精剪拆句）
- **落盘自校验（2026-09-20）**：生成后比对剪切稿条数与字幕轨条数，不一致逐条列原文当场曝光——静默丢条（ASR 尾部时间戳滞后被静音细剪裁掉，实测 0.8s）不再靠人工反查；rebase 对尾部滞后的钳制容差 1.5s
- **标注轨** = 红色置顶文本，自动标第②层处理不了、留给精剪的点（句内叠词口吃等）。**导出成片前删掉该轨**
- **加速不属粗剪（2026-09-19 用户决策）**：粗剪所有段 1.0x 交付，加速/BGM/花字全在精剪域。`--narr-speed/--gap-speed` 参数保留为精剪步骤可用（如参考天书实测的 2.0x/6.0x），但默认必须 1.0
- 词级跳剪：转录产出的 `.cuts.json`（句首"然后"等口头禅的词级时间）在生成草稿时自动从音频抠掉，字幕文本同步剥字；`--no-cuts` 关闭
- 依赖 `pip install pyJianYingDraft`（轻量）；草稿写进剪映草稿目录（默认 `AppData/Local/JianyingPro/User Data/Projects/com.lveditor.draft`，不同装法用 `--draft-folder` 指定），打开剪映首页即见
- 要独立粗片文件（如发抖音版先用）→ fallback 走 `srt_cut.py` 重编码出片
- **要"一进一出"的分段成片**（每素材一个不拼接的粗剪文件，和草稿并存）：`python scripts/srt_cut.py --seq "素材1.mp4=剪切稿1.srt" "素材2.mp4=剪切稿2.srt" --out-dir 待粗剪/4_粗剪成片`——每素材输出 `<名>_粗剪.mp4` + 同名对齐字幕 srt（词级洞+静音细剪与草稿同款节奏）。重编码以分钟计，**后台跑**，不挡草稿交付；跑完 organize 归位到 `4_粗剪成片/`

精剪重点提示用户：标注轨逐条处理（补录/加速/文字贴片），关键步骤动画/字幕强调，结尾 CTA 往"存着照做"上靠（认知②）。

### 5. 副产物归档（喂 review，闭环）

- 逐字稿（保留原文含口误，**不是**剪切稿）→ `transcripts` 配置目录下 `第N期_标题_逐字稿.md`，frontmatter 标期数，正文末尾追加一行漏斗数据：`原始 3h → ②粗剪后 12m（初选删 N 条 + 词级洞 M 个）`
- 这份文件就是 review 复盘时逐字稿分析的输入，归档后告知用户"复盘时不用再贴逐字稿了"
- vault 改动 `git add . && git commit -m "AI: 剪辑提效 第N期 逐字稿归档"`（知识库是 git 仓库时）

### 6. 发布后复核（与 review 闭环，剪完不是终点）

粗剪成片发布后，进 review 复盘时**额外核对三个"粗剪效果信号"**：

- **开头 3 秒流失 / CTR**：异常 → 回查初选是否删伤了开头条目、或词级挖洞切了开头
- **留存曲线中段尖峰**：流失时间点对照剪切稿——尖峰处若是挖洞/删句的接缝，说明节奏伤了
- **完播 vs 同类对照**：偏低且曲线平滑流失 → 初选可能删得太碎（口吃保留策略过头），回调删除阈值

复核结论写回当期复核单/剪切稿备注，跨期积累初选规则的校准数据。

## 错误处理

| 情况 | 动作 |
|---|---|
| 找不到 ffmpeg | `winget install ffmpeg` 或 `pip install imageio-ffmpeg`（脚本自动发现两者） |
| 切字 | `--pad` 加大重跑 |
| 转录警告"token ≠ 时间戳，按比例兜底" | 词级洞全丢（时间戳失真不可用）——脚本已自动试撇号/连字符合并；仍失败看警告里的可疑字符，多半是新标点/符号没归类 |
| 转录稿里还有口癖没剥 | 看它前一个字符：分句标点后没剥=bug（报修）；无标点连读（"选的是然后选"）无停顿不硬抠，留精剪 |
| 自校验报"丢 N 条字幕" | 看列出的原文：落在词级洞里的属正常（口播已挖掉）；其余是 ASR 时间戳漂移，对照静音检测手工核 |
| 没检测到静音（①层预览时） | 阈值不合适：噪大环境用 -30；素材本身没冷场就跳过这层 |
| ModelScope 模型下载慢（几百 kB/s） | 用户开着 VPN——关掉直连（国内 CDN）；pip 装 funasr 才需要开 VPN |
| 技术词识别错 | `--hotword` 塞热词重跑；常见错拼沉淀进 `scripts/asr_fixes.json`（跨期复用），条目特有的进决定.json fixes |
| funasr 首跑卡在下载 | 模型 ~1.2G 逐个下，耐心；卡死删 `~/.cache/modelscope` 对应目录重拉 |
| jy_draft 报草稿目录不存在 | 剪映全局设置→草稿位置 里看实际路径，`--draft-folder` 指定 |
| 剪映打不开生成的草稿 | 剪映版本比库的支持矩阵新——升级 pyJianYingDraft（`pip install -U`）；仍不行退回 srt_cut 出粗片 + 双 SRT 导入（文本→本地字幕→导入字幕） |
| Git Bash 造测试素材 | 别放 /tmp（和 Windows Python 路径体系不通），放工作目录 |
| 素材全程无口述 | 第②层做不了，如实告知本期只能①+人眼，重点提醒下期口述（认知①） |

## 工作区规矩（2026-09-19 实测沉淀）

- **跑完管线执行 `organize.py <待粗剪目录>`** 归位阶段目录（1_原始/2_静音压缩/3_转录初选/_工具），不靠人肉整理；被占用的文件跳过并报告，关程序后重跑
- **转录一律单批全量**：`asr_funasr.py 段1 段2 …` 一次吃完全部素材，模型只加载一次；按"编码完成先后"分批跑是白烧 2-4 min/次
- **初选决定走 select.py，不再每期手写初选脚本**：AI 只产出 `初选决定.json`（iron/repeat/fixes）+ `--dry` 核验 + `--apply`；常见错拼沉淀进 `asr_fixes.json` 不重打
- **依赖核验走 env_check.py 缓存**（首跑写技能安装目录 `_env_verified.json`，之后秒过不重验）；报缺包时重依赖（torch 级）仍要用户点头才装
- **修错表应用前先 dry-run**：将替换的原/改句子对照打印过目再落盘（SSP三二→SESP32 返工教训；select.py --dry 内建）
- **跨文件重复不做自动检测**：措辞不同的同场景重拍纯文本抓不到（实测 sim 仅 0.32），人工对读兜底；**同段内**重复由 select.py --scan 预聚类辅助 + AI 拍板
- **零重编码架构（2026-09-19 落地）**：①层物理重编码已退出默认流程（实测省 ~13.5 min），转录直吃原素材音频（VAD 跳静音，30 min 素材 ~1.5 min），全流程单一原始时间轴；silence_trim.py 保留为预览/独立粗片用

## 红线

- 只处理**用户自己的素材**，不给脚本加任何爬取/下载他人视频的能力
- AI 初选一步到位直接出剪映草稿（2026-09-19 用户决策）；品味判断后移到精剪
- 重依赖（torch 级）安装必须用户点头，不擅自装
- Cookie/敏感信息不进任何 git 跟踪文件
