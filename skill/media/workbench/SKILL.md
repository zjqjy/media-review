# workbench · 素材生产工作台

口播定稿之后，**素材按口播逐行生产**。本技能做三件事：

1. **面板**（给人看）：`scripts/工作台.py` 解析口播脚本 → workbench.html——每行口播 = 一个生产任务（R01/R02/…），显示需求标签、已产出文件、状态（未制作/已产出/完成）
2. **目录规范**：`scripts/新视频项目.py` 建项目树——00_口播 / 01_字幕卡_HTML / 02_动效视频 / 03_实拍素材 / 04_成片
3. **AI 生产流程**（本节 = ZCode / Claude 的生产剧本）：状态与产出全走项目目录文件，双向无缝

## 状态与接口（文件即状态）

| 文件 | 谁写 | 谁读 |
| --- | --- | --- |
| 口播脚本 md（定稿，路径由用户给——通常在 obsidian 知识库） | 人 / AI | AI 与 工作台.py |
| `workbench_state.json` | AI 产出后更新；工作台网页授权目录后读写 | AI 与 网页面板 |
| `Rxx_名称.ext`（01/02/03 目录） | AI 产出 或 人制作 | 面板按行号自动挂接；人验收 |

`workbench_state.json` 结构：`{"updated": "...", "rows": {"R07": {"st": "已产出"}, ...}}`

## AI 生产流程（收到「做素材」类指令时照此执行）

**触发**：用户说「做素材」「按口播做素材」「把 Rxx 做了」「素材做得怎么样」

**流程**：

1. **定位口播**：用户给的 md 路径（知识库路径直接读），或项目 `00_口播/` 内的定稿副本。逐行解析分节表格（| 时间轴 | 口播 | 画面/素材 |），行号即出现顺序 R01/R02/…
2. **解析需求**：每行的「画面/素材」列即需求声明，按关键词分类：
   - 含 字幕卡 / 卡 / HTML → **cards 行**
   - 含 动效 / 动画 / Remotion / motion → **vibe-motion 行**
   - 含 实拍 / 真机 / 录屏 / 拍摄 → **实拍行**（只出拍摄清单，人拍）
3. **按类型生产**：
   - cards 行 → 按 [[../cards/SKILL.md]] 规范生成 HTML 卡（分步卡/自动卡模板，视觉规范 oil-cover 体系），命名 `Rxx_名称.html` 放 `01_字幕卡_HTML/`
   - vibe-motion 行 → 按画面类型路由社区技能：打字动画→claude-typer / 进度条→ruler-progress-render / 屏摄鱼眼→fisheye-motion / logo 动效→pixel2motion / 品牌片→brand-launch-video-star（`npx skills add vibe-motion/skills` 安装；社区新家 motionface.cc），产物放 `02_动效视频/`
   - 实拍行 → 写 `03_实拍素材/待拍清单.md`
4. **更新状态**：每完成一行 → `workbench_state.json` 该行 `st: "已产出"`（逐行更新，不批量攒）
5. **汇报**：各行产物路径 + 缺口清单（实拍待拍 / 未覆盖行）

**范围控制**：用户可指定「先做 R01~R05」「只做字幕卡行」「跳过 R13」——只处理范围内行。

**原则**：一行一产物、行号命名、逐行落状态；画面需求不明确时问用户，不猜。

## 命令

```bash
python scripts/新视频项目.py <项目路径>             # 建项目树
python scripts/工作台.py <口播脚本.md> <项目根>      # 生成/刷新面板
```

## 红线

1. 工作台面板与状态文件只做**关联与状态**，内容产出归 cards / vibe-motion 技能
2. 行号一旦定稿不改（状态按行号索引）；口播改动后行号重排需用户确认
3. 画面需求不明确 → 问用户，不猜
