# media-cut · 剪辑提效（发前粗剪）

**核心概念：三层漏斗，每层只干一件事。** 痛点是教程类视频 60:1 的素材压缩率（成片 5 分钟，原始素材 3 小时），最费时的不是精剪，是**看素材选段**。慢的根源是无声素材没有时间索引，只能人眼过——解法不是手快，是让机器先吃掉"确定没用的大段"，人只处理剩下的。方法论出处：vault `30_方法论/剪辑提效工作流.md`。

## 两个关键认知（所有决策的依据）

1. **改造录制习惯比换工具更值**：录屏时同步口述（说得烂没关系，反正要剪）——口述就是时间标记 + 内容索引，转录后剪辑从"看片"变"改稿"，且转录产物就是逐字稿（复盘系统的输入自动就有了）。素材全程无口述（纯操作无声）→ 第①层只能砍冷场，第②层无从下手，提醒用户**下期**录制时加口述
2. **工具类内容在抖音，收藏率比完播率重要**（8.94 万那条完播才 0.99%）——粗剪别死磕把完播做高，把"可以存着照做"的清单感做出来

## 前置

- 脚本：本 skill 目录下 `scripts/silence_trim.py`（零依赖，仅需 ffmpeg）
- ffmpeg 自动发现：PATH → `imageio_ffmpeg` 自带二进制。都没有 → 让用户 `winget install ffmpeg` 或 `pip install imageio-ffmpeg`
- AutoCut / FunClip 装在用户侧（重依赖，选一个）：[AutoCut](https://github.com/mli/autocut)（李沐，Whisper）或 [FunClip](https://github.com/modelscope/FunClip)（阿里 FunASR，中文更稳 + LLM 选段）。二选一实测还没做，用户没装时推荐 AutoCut（`pip install autocut`，首跑下 Whisper 模型），识别差再换 FunClip
- 逐字稿归档需要 vault 路径；若当前工作目录就是 vault（能找到 `20_自媒体/`），路径相对 cwd

## 流程

### 0. 判断入口（不必每期都从头）

| 用户现状 | 入口 |
|---|---|
| 还没录 / 在规划 | 先讲认知①（口述录制），这是最大的效率杠杆 |
| 只有原始素材 | 从第①层开始 |
| 已有带时间戳的转录稿（md/srt） | 跳过①②的转录，直接做 AI 初选 |

### 1. 第①层：静音压缩（机器全包）

```bash
python scripts/silence_trim.py 素材.mp4 [--db -35] [--min 2.0] [--pad 0.3]
```

自动砍 >2s 的无人声冷场（操作间隙/编译等待/切窗口），音视频同步删，输出 `<stem>_trimmed.mp4` 到**素材同目录**。参数调优：

| 症状 | 调整 |
|---|---|
| 环境噪声大，正常停顿没砍到 | `--db` 提到 -30（阈值高于噪底才判静音） |
| 录音很干净，砍得太狠 | `--db` 降到 -40 |
| 切到字了（说话被切半个字） | `--pad` 加大（0.3 → 0.5，每段两头多留缓冲） |
| 自然停顿也被砍，节奏发紧 | `--min` 加大（2 → 3，只砍更长的冷场） |

注意：重编码 3 小时素材耗时以几十分钟计，**后台任务方式跑**，别阻塞对话；跑完向用户报砍掉比例（本期漏斗数据，归档时要用）。

### 2. 第①层产出 → 第②层转录（用户跑）

- **AutoCut**：`autocut -t 素材_trimmed.mp4` → 生成 `素材_trimmed.md`（每行一句带时间戳，**删行 = 删视频**），副产物 SRT 字幕
- **FunClip**：中文技术词 + 口音场景更稳，自带 LLM 选段（用它的话这步在它那边完成一半）
- 用户已有其他渠道的转录稿 → 直接用，不重转

### 3. 第②层核心：AI 初选（本 skill 的主力工作）

1. 要**内容大纲**：读 `20_自媒体/复盘/_下期规划参考.md` 或本期规划笔记；没有就用户口述三句——给谁看 / 解决什么问题 / 关键步骤
2. 读转录稿逐句标三类：
   - **保留**：核心步骤、结论、金句
   - **删**：跑题、重复、死胡同、口误重录的前一次
   - **收紧**：内容要但表述啰嗦——只标记，**不改正文**
3. **删行随意、行内只修错不改写**（AutoCut 剪切只看行头时间戳：删整行 = 删该段；行内修错别字/专有名词也安全，SRT 字幕反而更准；但**别合并/拆分行**——一行对应一段，行结构乱了剪切就乱。"收紧"不改正文——md 里改了字，音频还是原话，字幕会和口播对不上，只做标记留给第③层加速或补录）
4. 产出两个文件：
   - **剪切稿**：删行后的 md（AutoCut-ready，用户复核后 `autocut -c 剪切稿.md` 直接出粗片）
   - **复核单**：删了哪些行 + 为什么，拿不准的标"建议保留"让用户定
5. 初选时用认知②打分：优先保住"清单感"（步骤完整、结论前置、每步可跳读），别为完播砍步骤

**铁律：AI 初选不替用户拍板**——用户复核剪切稿之后才跑 `autocut -c`。与 media-review 的写回确认制同源。

### 4. 第③层：精剪交接

交接清单（给剪映/PR）：粗片（autocut -c 产出）+ SRT 字幕 + "收紧"标记清单。精剪重点提示用户：关键步骤动画/字幕强调，结尾 CTA 往"存着照做"上靠（认知②）。

### 5. 副产物归档（喂复盘，闭环）

- 逐字稿（保留原文含口误，**不是**剪切稿）→ `<vault>/20_自媒体/复盘/逐字稿/第N期_标题_逐字稿.md`，frontmatter 标期数，正文末尾追加一行漏斗数据：`原始 3h → ①静音压缩后 1h02m（砍66%）→ ②粗剪后 12m`
- 这份文件就是 `/media-review` 复盘时逐字稿分析的输入，归档后告知用户"复盘时不用再贴逐字稿了"
- vault 改动 `git add . && git commit -m "AI: 剪辑提效 第N期 逐字稿归档"`

## 错误处理

| 情况 | 动作 |
|---|---|
| 找不到 ffmpeg | `winget install ffmpeg` 或 `pip install imageio-ffmpeg`（脚本自动发现两者） |
| 切字 | `--pad` 加大重跑 |
| 没检测到静音 | 阈值不合适：噪大环境用 -30；素材本身没冷场就跳过这层 |
| AutoCut 技术词识别差 | 换 FunClip 试；或转录 md 保持行结构不动、只修专有名词拼写后再走初选 |
| Git Bash 造测试素材 | 别放 /tmp（和 Windows Python 路径体系不通），放工作目录 |
| 素材全程无口述 | 第②层做不了，如实告知本期只能①+人眼，重点提醒下期口述（认知①） |

## 红线

- 只处理**用户自己的素材**，不给脚本加任何爬取/下载他人视频的能力
- AI 初选结果必须经用户复核才剪切落地（品味判断是人）
- Cookie/敏感信息不进任何 git 跟踪文件
