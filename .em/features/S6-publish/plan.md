# plan — S6 publish 三平台自动发布子技能（ego 直驾 + SOP 教材化）

> 档位：中 · 2026-11-07 · R0 四问澄清 + GitHub 调研（social-auto-upload / auto-publish / omnipost）→ 方案A 定音
> 用户原话锚点：「尽量模拟人类输入」「每个平台字数限制不一样要调用」「先调用 github 有没有项目参考（尽量模拟人操作）」

## 需求理解（R0 Q→A）

| # | 问题 | 结论 |
|---|------|------|
| Q1 | 人工确认闸门 | **发前一次确认**：agent 按各平台字数限制出三份标题+简介草稿（可逐平台改）→ 用户说「发」→ 三平台全自动走完（含点发布按钮）；首跑真发例外=用户在场盯 |
| Q2 | 登录态 | **ego 持久 profile**：每平台独立 profile 存登录态，失效时提示人工扫码，之后长期复用；主号 profile 与 benchmark 的 B站小号彻底隔离 |
| Q3 | 素材入口 | **对话加载附件 + 指定目录/路径**都收，agent 不自动猜文件；视频=剪辑链路成品整片（剪映导出），封面=cover 三画幅按平台选（B站16x9/小红书3x4/抖音竖版） |
| Q4 | 验证方式 | **dry-run 停「发布」按钮前**：三平台表单全填完截图过目（用户仅一期真视频，不烧测试内容）；通过后首跑真发用户在场 |

默认口径（摘要确认时未纠正）：
- 确认单含 B站分区+标签/话题（B站不选分区发不了）
- 三平台顺序发布+随机间隔（不同时发，更像人）
- 不做：发布后数据回收/评论管理、定时排期、多账号矩阵
- 人机验证（验证码等）→ 停下 handOff 交给人；模拟人类=正常操作不被误伤，不是反风控攻击
- 素材进来什么传什么，不加工视频/封面

## 方案

### 候选对比

- **A. agent 直驾 ego-browser + SOP 教材化（选定）**
  思路：publish 子技能 = 三平台上传 SOP（入口 URL/表单步骤序/字数常量表/人类节奏参数）+ 辅助脚本（字数校验/确认单生成/截图归档）+ 门面路由；发布时 agent 按 SOP 现场 snapshot 认路、选择器现场比对不硬编码。
  优：零第三方重依赖；抗页面改版（agent 看现场自己认路）；ego 原生支持上传/扫码/截图；dry-run 天然可做；与「用 ego」要求一致。
  缺：每次发布耗 agent 轮次；首次 SOP 编写要真踩三平台创作者页面。工作量 M
- **B. 移植 social-auto-upload 的 Playwright 内核**
  优：运行时零 token、确定性强。缺：cookie 存它家 storage_state 与 ego profile 两套皮（违背 Q2）；CSS 选择器腐烂原样继承；自动化指纹易触风控（benchmark 在 B站吃过亏）；dry-run 要魔改其直发流程。工作量 M
- **C. 直接调 social-auto-upload CLI（sau）**
  优：最省事。缺：黑盒直发做不到「停按钮前」（Q4 直接被否）；cookie 同 B 两套皮；改版受制上游。工作量 S

**选定 A。理由**：唯一同时满足「用 ego / 模拟人类 / dry-run 停按钮 / 登录态单套皮」四条硬约束；调研项目共同死穴 = CSS 选择器腐烂（页面改版即坏、修复等上游），故**只抄知识（流程步骤/字段/字数上限/坑位）不抄运行时**。

### 关键技术点

- ego 能力映射：视频上传 `setInputFiles` / `waitForFileChooser`；扫码登录 `handOff()` 交人、确认后 resume；页面认路 `snapshot()`（语义 ref，抗改版）；dry-run 存证 `screenshot()`；富文本简介 `keyboard.paste({ text })`
- 人类节奏：三平台顺序发布、动作间随机延时、关键输入框逐字键入（可行时），绝不同时开三平台
- 字数常量表：三平台标题/简介上限、B站分区树、话题格式——**数值从调研源码提取 + 实测校准后固化 `platforms.json`，未经校准不得写死进 SKILL.md**
- 失败语义：表单填一半失败 → 截图+人话报错，不盲目重试不乱点；遇人机验证 → handOff 交人
- 双拷贝纪律：仓库 `skill/media/publish/` 与装位同步（S6-B 起，收尾再 diff 对拍）
