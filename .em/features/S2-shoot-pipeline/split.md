# 需求拆分 — S2 shoot-pipeline

> 阶段1 产出 · 2026-11-05 · 用户修订：**不要 workbench**（素材关联自立门户）；③按工具盘点扩为「不止 cut」

## 四子系统

### 1. 呈现方式批注（拍摄计划层）
- 类型：UI + 旁车数据扩展
- 简述：draft 工作台定稿版上，块级为主+可圈句标「以什么方式呈现」——人工拍摄（拍什么/场景提示）/ AI 制作（类型枚举 cards/vibe-motion/aigen/其他 + 自由指令文本）；产出拍摄计划清单
- 落点：draft 子技能扩展（S1 底座）

### 2. 素材关联（拍摄回交层）
- 类型：存储/映射
- 简述：拍摄回来的原始片段 ↔ 呈现批注映射——命名约定优先 + AI 匹配兜底 + 人工确认收尾；多对多+候选/选用状态；缺拍显性清单
- 落点：新子技能 `shoot`（不碰 workbench）

### 3. 剪辑阶段编排（工具箱对接，不止 cut）
- 类型：UI + 工具编排
- 简述：剪辑批注挂素材表条目（截哪段/效果/接哪）；缺画面按①批注显式生成补制任务（cards/vibe-motion/aigen）；编译 cut 认的输入，剪辑本体走 cut 规程，post 收尾
- 落点：`shoot` 子技能内

### 4. Agent 协作协议（贯穿层）
- 类型：通信/协议
- 简述：①②③ 产出统一成 markdown 人读清单 + shoot.json 机器读，agent 完成后回写状态字段；项目目录内置 AGENT_PROTOCOL.md 规程卡，zcode / claude code / codex 读卡即接入

## 链路

```
定稿md ──①呈现批注──▶ 拍摄计划清单 ──拍摄──> 素材
              ④agent协议贯穿
素材 ──②关联──> 素材表 ──③剪辑批注──> cut粗剪 ──post──▶ 定稿
```

## 与现有工具的关系

| 工具 | 在本链路的角色 |
|------|------|
| draft（S1） | ①的宿主：定稿版加呈现批注模式 |
| cut | ③的执行体：吃编译出的结构化素材目录+剪辑说明 |
| cards / vibe-motion / aigen | ①②③的 AI 制作类型枚举，补制任务的路由目标 |
| post | 成片后处理，照旧 |
| workbench | **不参与**（用户明确排除） |
