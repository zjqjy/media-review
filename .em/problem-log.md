## P1 成片残留底噪段 + 人声间空白未删净（2026-10-10，已闭环）

**现象**（用户报，R02_演示.mp4 实测复核）：粗剪成片里 ①录制底噪、没有人声的段落没剪掉——最严重一处输出 1:18→3:27 连续 2 分钟只有开头一句人声；②人声与人声之间的空白删不干净——输出里多处 4~8s 无话区间（5:29→5:36、6:09→6:13、6:19→6:26 等）。

**根因**（两个 bug 同根，叠加放大）：
1. ASR 拉伸条目：底噪素材上 FSMN-VAD/Paraformer 把长噪声并进转录条目（剪切稿 #27：`00:05:59→00:13:33` 共 7.5min 只有 10 个字），初选按内容保留后 srt_cut 保住整段区间；
2. 能量细剪失效：区间内静音细剪靠 `silencedetect=noise=-35dB`（采样级瞬时电平），底噪段里的瞬时毛刺（鼠标/碰撞，实测峰值 -29dB）不断打断 ≥0.8s 的静音连续段——均值 -44.5dB 的纯噪声区被判成"不是静音"。
3. 实测定锚：真静音区 mean -52.6dB（-35dB 可检出）；残留噪声区 mean -44.5/max -29.2dB；系统音区（1695-1707s，调出收集窗口的操作音）mean -21.6dB——**响度维度分不开人声和噪声**。
4. VAD 验证：FSMN-VAD 独立跑（fsmn-vad）在 R02 上出 141 个人声岛共 526s；paraformer 去 VAD 直听写 1693-1713 证实 1695-1707 的响声无词、真词全部落在 VAD 岛内——**VAD 是可靠的人声 oracle，ASR 条目时间戳才是撒谎的**。

**修复**（silence_trim.detect_silences 双档）：
- `db=None`（新缺省）智能模式：FSMN-VAD 人声岛补集挖洞（`holes_from_speech`，岛两侧 pad 0.25s，洞 <min_s 不挖），结果缓存 `<stem>.vad.json`（mtime 键）；funasr 不可用/失败回退能量 -30dB
- `db` 给定：纯能量模式（旧行为不变）
- 接线：srt_cut / jy_draft `--db` 缺省改 None，qa_backfill 硬编码 -35 改 None；select.py --scan 新增「拉伸条目候选」警示（文本密度 <1.5 字/秒 且 ≥8s）

**验证**：43 个单测全过（含 R02 真实岛回归）；span 重建对比 537.4s→428.9s（再砍 108.4s 纯噪声），四个问题源区间全挖 ✓；真实出片后全片最长字幕 8.83s（原 128s），142 条零丢失。

**遗留**（跟踪）：
- ~~**P1a 条目边界切字**~~ → **已修（2026-11-05，S2 期 P1a 专项）**：`srt_cut.build_spans` 加 VAD 焊回——相邻保留条目间隙 < `WELD_GAP=2.0s` 且 `vad_speech` 岛链横跨两端（`VAD_BRIDGE_TOL=0.2s`）则连间隙合并；VAD 不可用自动降级旧行为；`jy_draft`/`qa_backfill` 已接线传参。29 个单测含案卷合成复现（R02 #71→#72 间隙 1.34s、真词「个」1711.53-1711.77 焊回后覆盖）。**待标定**：两阈值需真实素材跑一遍定标（R02 素材+剪切稿 srt，`--weld-gap 2.0` 与 `0` 各出一条对比听 1711s 附近），仓库暂无该 srt 产物。

## P5 真凶落网：段落乱跑与拖拽无关（2026-11-05，用户三报后自查定案，当日闭环）

**现象**：P4 修完工具条几何后用户仍报「点了还是跑」。截图显示块序被打乱且工具条已不压字。

**根因**（真正主犯，此前三轮全在冤案拖拽上打转）：`refreshBlockEl` 里 `replaceChild(newEl, old)` 后画蛇添足 `insertBefore(next, old.nextSibling)`——old 已脱离 DOM，`nextSibling` 恒为 null → insertBefore(next, null) = **把「下一块」append 到文档末尾**。每次块失焦（commitBlockEdit）或打批注（addComment）都触发，旁边的块就飞走。S.blocks 数组自始至终正确——**乱的纯是 DOM 显示层，盘上稿子逐字未伤**（parse 复核：15 个标题顺序全对）。

**修复**：`old.replaceWith(...)` 一行保位，删除补位逻辑。

**闭环**：ego R7 按真实用户流四断言全过——改字失焦/打批注/连改两块后 DOM==数据、文档末尾恒为 51,52,53；测试改字未落盘、测试批注已清理。

**教训**：①「点击乱序」类问题要完整复刻用户操作流（含失焦重绘），只测 click 本身测不到；② DOM 显示层与数据层要分开断言（本次数据层一直是对的，三轮 E2E 都只查了数据层）。

## P6 仓库地雷：cut/scripts/select.py 遮蔽标准库 select（2026-11-05，S2-C 开发期发现，**开放**）

**现象**：任何把 `cut/scripts` 插进 `sys.path` 的代码/测试，之后 `import select`（socket/HTTPServer 间接依赖）会拿到 cut 的 select.py 假模块——S2-C 的 4 个 API 测试当场烧 10s 超时（HTTPServer 线程死）。

**现状缓解**：test_shoot_match.py / test_shoot_cut_compile.py / test_shoot_export.py / test_agent_writeback.py 顶部已「钉真 select 进 sys.modules」防护。

**建议修法**（未做，改文件名有牵连）：`cut/scripts/select.py` 改名（如 `selector.py`）+ 全仓 grep 引用点同步；或至少在文件头注明地雷身份。

**教训**：脚本目录与标准库同名是全局性毒药，新子技能测试一律带钉子防护。

## P7 僵尸旧服务吞保存：Windows 双绑定让端口爬位永不触发（2026-11-05，当日闭环）

**现象**：用户在 draft 工作台点「保存」显示成功、开「历史」却是 0——`.draft_history` 目录从未建立。此前一天还出现 8791 端口的孤儿页签（服务已死页面还活着，点「添加呈现批注」静默失败）。

**根因**：`ThreadingHTTPServer` 继承 `allow_reuse_address=1`，Windows 的 SO_REUSEADDR 语义允许**第二个进程绑定同一监听端口**——「端口被占爬位 +1」的重试循环从未触发过。实测两进程同挂 8765，流量随机分：17:01:55 那次保存被旧代码僵尸进程（无快照功能）接走，新服务根本没经手；`历史`查询打到新服务读盘自然为 0。

**修复**：draft/shoot 两服务加 `allow_reuse_address = False` 子类（DraftServer/ShootServer），占用检测真失败→爬位+1 生效（实测 8877 被占自动改 8878）；历史弹层空态文案改「内容有变化的保存会自动快照（没改字不重复快照）」防同类误解；新增 tests/test_server_port_climb.py 三个断言钉住。

**教训**：①「被占重试」类逻辑必须实测占用场景——绑定成功≠服务正常，双绑定是静默故障；② 复现时 subprocess 里 print 要 `-u` 无缓冲，terminate 后 stdout 缓冲区全丢；③ 排查「功能坏了」先查有几个进程在监听（`netstat -ano`），孤儿页签+僵尸服务是本机长会话的常态污染。

**关联**：select.py 地雷（P6）在本案再次显形——新测试文件按字母序插在钉子之前也会中招，新测试文件一律复制钉子头部。改名建议维持 P6 原案（post/final_sub.py `from select import load_global_fixes` 有牵连，需一并改）。

## P8 素材面板必须先跑 CLI 才能挂素材（2026-11-05，用户 /em result 报，当日闭环）

**现象**：用户在真实项目（20261101_ego 浏览器期）打开 shoot 面板，素材区空、只有一句「先跑 素材回收.py」——素材没按 R 命名约定拍回来时，人被流程卡死，无法手动登记。

**根因**：素材登记的唯一入口做成了 CLI（文件名约定匹配），面板只消费它的产出——把「提效路径」误当成了「唯一路径」。

**修复**：手动添加升为一等路径——①服务端 `POST /api/footage/add`（登记+顺手挂批注，id 从现有最大号顺延、同文件幂等跳过、相对路径按项目根解析、引号净化、**根外素材拒收**——剪辑交接按项目根复制）+ `GET /api/browse`（列目录子目录与素材文件）；②面板 batchbar 加「＋添加素材」弹层（浏览目录→勾文件→勾批注→添加），空态文案改为双路径；③SKILL 剧本更新（素材回收降级为命名约定批量提效路径）；④测试 +5 例（登记/幂等/根外拒收/未知批注/净化）。294 全绿。

**教训**：设计「A 提效、B 兜底」时，兜底路径也要做到一等公民——用户素材永远不按你的约定来。

## P9 剪辑批注保存后「没办法再改」+ 任务区缺工具挂靠（2026-11-05，用户 /em result 报，当日闭环）

**现象**：真实项目素材卡上 ✂️ 批注按了确定（Enter 保存）后，想再改没有入口——黄色批注条点了没反应。任务区只有任务类型（card/motion/aigen），看不出该用 media 技能栈的哪个工具执行。

## P10 「读取失败: unknown endpoint」——新页面配旧服务进程（2026-11-05，用户 /em result 报，当日闭环）

**现象**：P8 的「＋添加素材」弹层打开后目录列表报「读取失败: unknown endpoint」——前端静态文件每请求现读盘（刷新即新），Python 路由却在**进程启动时冻结**；用户跑着的 shoot 服务是 P8 改动前启动的，没有 /api/browse 路由。

**根因**：同 P7 一族（僵尸进程/孤儿页签/旧进程）——本机长会话下「页面新、进程旧」无任何提示，报错是裸的 "unknown endpoint"，用户无从知道要重启服务。

**修复**：①服务端 `API_VERSION=2` 随 /api/project 下发（约定：加新路由/改响应结构必须 +1）；②前端打开项目时比对 `MIN_API_VERSION`，旧进程在状态栏+toast 明说「服务是旧版进程，请重启」；③api() 把 "unknown endpoint" 翻译成人话（「重启 shoot 服务再用此功能」）。294 全绿，装位同步。

**教训**：前后端同仓不同步是长会话本地工具的常态——能力握手（版本号）要在一开始就设计进去，出了事再补已经砸了三次。
